# The Prompt

```md title="The Prompt"
I am a Technical Writer.

You are an Information Architect and a programmer/developer, specializing in the tools named here after.

Our team is changing our tech stack to use .md and.mdx files written in the tool VSCode.

We will be using Github as a repository.

We publish an online user guide.

We use Docusaurus to build the online user guide.

We use a Docs-as-code method to authoring.

Hosting is currently with AWS but this may change.

We are building an open-source tech stack, as you can tell from the tools used.

We also want to keep costs as low as possible, so free tools are preferred where those are reliably trustworthy.

Within the team, we use GitHub Pull Requests for peer review, using the function of being able to add a comment associated with the line of content in the file.

As we can download the branch from GitHub, where needed we can host a local version the online user guide to review final product result.

We do not have an efficient or standard method of requesting review of user guide content by colleagues who do not use GitHub.

I need to investigate possible solutions to this issue.

Solution should include:

- I need to determine a media for the review version, this will be dependant on the tooling (i.e. internal hosted review version of the online version, or viewable as content in something like Figma, or in some other software?).

- Reviewers feedback comments in the review version should be linked to the content line in some way, to allow pinpointing the location (line number) in the source file that needs to be amended

- Reviewers should have simple access and comment addition process

- Version recording/tracking

- Ties into the new tech stack neatly if possible

We can use other tools available to us already, should they be suitable within a proposed solution. They are:

- Miro
- Figma
- Confluence
- Jira
- GitHub (Rich Diff feature)
- BackStage.io

I hope to be able to create a process where a message, such as email or Teams chat, Jira (via Jira automation, which is investigated elsewhere and is not to be instructed or advised on here) etc. such that the reviewer can click a link to be taken to the review content, and be able to click into the reversion to add a comment for feedback (be that a request for edit, removal, or something else).

The sought for functionality may not be available or possible without a self-developed 'bridge' to link any shortfalls. I imagine a scenario where some data can be collected, but no method exists to connect that to the next step, such as being able to record the feedback comment and location information, as an export. I could potentially use the exported data as an import to a custom script to amend files as per the imported content to add these comments to the correct file at the correct line number.

This investigation will only concentrate on currently available possible solutions than can be created. No instructions or directions are needed.

Supply details of possible solutions to meet the criteria I have presented at a high level. (Example: Product A and Product B connect to achieve X part of the desired solution)

It is not essential the review content be as per final online version in terms of being rendered, so long as it is plain text, some formatting to respect headers, bold, lists, tables etc. would suffice. The aim is to remove the 'code' aspects.

Supply pro's and con's for each possible solution.

Supply references to all sources you use as I will need review these sources, and provide them as evidence of my research efforts.

Please be candid and matter of fact in your response as well.

If something is not possible, or there is simply no answer, say that is the case and do not generate a fiction that provides an answer.
```
